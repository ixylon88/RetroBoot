RetroBoot – Unvollständige MBR-Kopie im Journal verwerfen

Deutsch

Der Stromausfall ist beim Kopieren des geplanten MBR ins Journal nachgestellt.
Die Partitionstabelle auf der Systemfestplatte hat noch ihren alten Stand.
Die Rettungsdiskette kann die angefangene Kopie aus dem Journal entfernen.

1. ZIP entpacken. Beide Platten an die ausgeschaltete BIOS-Test-VM anschließen.
   Primäres Gerät 0    (primärer Master)    RB82-System.vdi
   Sekundäres Gerät 0  (sekundärer Master)  RB82-Sicherung.vdi
   Deutsch/journal-recovery.img in A einlegen und von A starten.
2. Es erscheinen die Meldung zur unvollständigen MBR-Kopie und der betroffene
   Sektor. Esc bricht vor dem Schreiben ab.
   Die neue MBR-Kopie ist unvollständig. Der MBR hat den alten Stand.
   MBR-Kopie im Journal RBTXN.A, LBA 0x00001B95
3. J stellt den alten Stand in diesem einen Journalsektor wieder her.
   Alter Stand im Journal wiederhergestellt. Partitionstabelle geprüft.
   RB JOURNAL RECOVERY PASS
4. Mit denselben Platten erneut von A starten.
   Kein Partitionswechsel offen. Beide Journalkopien sind geprüft.
   RB JOURNAL RECOVERY PASS

English

The test disk models a power loss while copying the intended MBR to the
journal. The system disk still holds the original partition table. The rescue
diskette can discard the unfinished copy and verify both baseline records.

1. Extract the ZIP and attach both disks to the powered-off BIOS test VM.
   Primary Device 0    (primary master)     RB82-System.vdi
   Secondary Device 0  (secondary master)   RB82-Sicherung.vdi
   Insert English/journal-recovery.img in A and boot from A.
2. The screen identifies the unfinished copy and its sector. Esc cancels
   before the write.
   The new MBR copy is incomplete. The live MBR still has its old contents.
   MBR copy in journal RBTXN.A, LBA 0x00001B95
3. Y restores the baseline copy to this single journal sector.
   Journal baseline restored. Partition table verified.
   RB JOURNAL RECOVERY PASS
4. Leave the disks attached and boot from A again.
   No partition switch is pending. Both journal copies verified.
   RB JOURNAL RECOVERY PASS

Recovery scope

An unfinished first prepare snapshot can be discarded while its header and
old MBR copy exactly match the intact sequence-1 baseline in the other slot.
The live MBR must match that baseline in full. The independently approved MBR
must pass the normal visibility-only journal checks. In the unfinished sector
there must be at least one changed byte from that approved MBR and a later
change still missing. A partial discard may have restored the start of the
copied prefix. Unrelated changes or a partly published header block this path.

Confirmation writes one sector at the audited snapshot address. The diskette
flushes and reads it back, reopens the external backup, verifies both complete
baseline records and rereads the live MBR. Two matching baseline records and
the matching live MBR produce the idle result on a cold boot, with zero writes.

When the first prepare header is missing or partly written over its seed,
the other slot must hold a valid sequence-1 baseline matching all 512 live
MBR bytes. The prepare slot must contain the same old snapshot and the entire
independently approved new snapshot. The header on disk must match an exact
prefix of the derived sequence-2 prepare followed by its seed suffix. The
normal journal decoder must accept the proposed pair. Before confirmation the
diskette shows the prepare sector, the MBR differences and both completion
sectors. It reads back the physical prepare and validates both slots again
before issuing the first LBA 0 write. A restart after the prepare write can
resume the ordinary prepared switch.

An LBA 0 repair requires a fully valid sequence-1 baseline and sequence-2
prepare, a valid live layout, and independent approval of the entire intended
MBR by the floppy witness and the published external backup. The complete live
sector must be the old snapshot or exactly a prefix of the intended snapshot
followed by the matching suffix of the old snapshot. Only supported primary
type and active bytes may differ. The screen compares the actual MBR with the
approved final bytes. Confirmation pins the complete observed MBR, hardware
enrollment, external publication, prepared record and audited journal sectors.
The repair rechecks all 512 live bytes before writing LBA 0.

If the approved MBR is already live, only the unfinished journal sectors are
offered. The completion slot must retain its exact old snapshot. With the seed
header intact its new snapshot may still be old, be complete, or consist of an
exact new prefix and old suffix. A partly written completion header is eligible
only once its new snapshot is complete.

Every changed sector is flushed and read back through BIOS and ATA. After a
confirmed MBR change the diskette reopens the backup and checks the current MBR
and both journal slots again before publishing any completion data. A restart
offers only the remaining sectors. A completed pair requires zero writes.
A changed protected byte, an invalid layout or an unexplained mixture in the
live MBR blocks the repair.
The normal boot-menu switch is a separate work package.
